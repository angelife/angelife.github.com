平台的优点是流量大、传播快、使用方便。但平台的缺点也很清楚：你的内容不归你控制，你的读者不归你联系，你的数据随时可能因政策、算法或商业决策而消失。

个人网站解决的是另一个问题：归属感。它不是用来获取流量的，而是用来存放那些你真正在乎的内容。

## 为什么还要个人网站

平台适合传播，个人网站适合沉淀。

在平台上写作，目标是迎合算法、吸引注意力、获得反馈。这本身没有错，但长期只在这种环境中写作，会慢慢改变你的写作动机。你会不自觉地写那些容易被推荐的内容，而不是那些真正重要的内容。

个人网站完全没有这个压力。你决定写什么、怎么写、放在哪里。没有算法干预，没有内容审核的隐形边界，没有"不更新就会被遗忘"的焦虑。它为长期写作提供了一个稳定的空间。

更重要的是，个人网站可以承载结构。一篇文章在平台上就是一篇独立的帖子；在个人网站里，它是系列的一部分、是栏目的一环、是知识库的一个节点。

## 核心判断

一个有长期价值的个人网站，不只是技术问题，更是内容策略问题。

技术上的选择其实很简单：静态网站生成器加 Git 托管，一次配置长期使用。真正的难点在于内容是否能持续更新、栏目是否能保持方向、旧文章是否能被逐步整理为更好的版本。

个人网站的建设不是一个项目，而是一个持续的过程。它需要三个前提：有一个愿意长期写下去的人，有一套稳定的发布流程，有一条让旧内容持续产生价值的整理路径。

## 怎么做

第一，选择稳定的技术方案。Hugo 或类似的静态网站生成器，配合 Git 保存版本，部署在 Netlify 或 Cloudflare Pages 上。一次配置后，更新就是写 Markdown 和推送代码。

第二，建立栏目和标签体系。不追求一次设计完美，而是随着内容增长逐步调整。好的分类能让新旧文章相互连接。

第三，逐步迁移旧内容。不是一次性搬完，而是按优先级：最有长期价值的先迁移、先整理、先发布。每迁移一篇，就更新一次摘要、标签和分类。

第四，保持发布节奏。哪怕每月只有一篇，也比突然爆发然后消失要好。稳定的输出会让网站慢慢生长。

## 结语

个人网站不是跟风复古，而是对自己长期写作的承诺。在平台时代拥有一块自己的根据地，不是为了对抗什么，而是为了让自己写下的东西有一个实在的归处。
