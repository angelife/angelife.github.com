# Gateway Missing .env API Keys

## Symptom

Gateway starts, connects to Telegram (shows "Connected to Telegram (polling mode)"), but every model API call fails with:

```
HTTP 401: Invalid API key.
Provider: custom  Model: deepseek-v4-flash-free
Endpoint: https://opencode.ai/zen/v1
```

The same API key works when tested directly:

```sh
source /opt/data/.env
curl -s https://opencode.ai/zen/v1/models \
  -H "Authorization: Bearer ${OPENCODE_ZEN_API_KEY}"
# Returns HTTP 200 with model list
```

## Root Cause

The s6 run script for per-profile gateways uses `#!/command/with-contenv sh` as its shebang. `with-contenv` imports the container's base environment but **does not source `/opt/data/.env`**. Even adding `. /opt/data/.env` in the script body doesn't work reliably because `with-contenv`'s environment isolation prevents sourced variables from reaching the exec'd child process.

The `config.yaml` has `api_key: ''` for most providers (keys live in `.env`), so the gateway process has no credential and gets 401.

## Detection

```sh
# Get the gateway PID
ps aux | grep "hermes gateway run" | grep -v grep

# Check if the env var is present in the process
cat /proc/<PID>/environ | tr '\0' '\n' | grep -i OPENCODE_ZEN
# If empty → the .env wasn't loaded
```

## Fix Applied 2026-06-20

Edit `/run/service/gateway-<name>/run` to extract the specific env var inline:

```sh
#!/command/with-contenv sh
set -e
export HOME=/opt/data
cd /opt/data
. /opt/hermes/.venv/bin/activate
# Load API keys from .env — with-contenv doesn't inherit sourced env
export OPENCODE_ZEN_API_KEY=*** '^OPENCODE_ZEN_API_KEY=*** /opt/data/.env | head -1 | cut -d= -f2- | sed "s/^['\"]//;s/['\"]$//")"
export HERMES_S6_SUPERVISED_CHILD=1
exec s6-setuidgid hermes hermes gateway run
```

### Verifying the fix

```sh
# Remove down file, start service
rm /run/service/gateway-default/down
/command/s6-svc -u /run/service/gateway-default/

# Check PID has the env var
ps aux | grep "hermes gateway"
cat /proc/<PID>/environ | tr '\0' '\n' | grep OPENCODE_ZEN
# Should show: OPENCODE_ZEN_API_KEY=sk-...

# Watch gateway.log for successful responses
tail -f /opt/data/logs/gateway.log | grep "response ready"
# 2026-06-20 03:01:38,652 INFO gateway.run: response ready: platform=telegram chat=780486548 time=14.9s api_calls=1 response=30 chars
```

## Affected Gateway Profiles

This affects ALL per-profile gateway services registered under `/run/service/gateway-*/` because they all use the same `with-contenv` run script template generated by `hermes_cli/service_manager.py::_render_run_script`.

## Affected Env Vars

Any provider API key stored in `.env` but not in config.yaml. Common ones:
- `OPENCODE_ZEN_API_KEY` (OpenCode Zen)
- `NVIDIA_API_KEY` (NVIDIA AI Foundation)
- `DEEPSEEK_API_KEY` (DeepSeek)
- `XUNFEI_API_KEY` (讯飞/Spark)
